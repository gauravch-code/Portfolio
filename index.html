01Local-first agent

Winnow

Inbox triage that decides locally first. A CPU classifier sorts most mail in milliseconds and calls an LLM only when it isn't confident. Every route comes with an explanation.

  1. Classify locally with MiniLM embeddings and scikit-learn, on CPU, at zero cost.
  2. Escalate only when uncertain to a PydanticAI fallback that reads the full thread.
  3. Learn from corrections through a guarded retraining loop with regression checks.

Key decisionDon't send every email to an LLM. Most mail is easy to classify, so a local model handles the confident majority in milliseconds for free, and the LLM budget goes only to the ambiguous tail.

02Agent observability

TraceGuard

An operations console for AI agents. It records every run so you can see the decisions, tool calls, failures, cost and human approvals behind each output.

  1. Observe: reconstruct every step and tool call of an agent run.
  2. Investigate: jump to the exact point where a run failed or drifted.
  3. Control: route uncertain support drafts into a human review queue.

Key decisionTreat agent output as a draft, not an answer. Uncertain support replies go to a human queue instead of straight to the customer, and every step behind them stays inspectable.

03Autonomous remediation

Agentic SRE Pipeline

Self-healing Kubernetes with guardrails. When memory pressure fires, an agent collects evidence and fixes the problem through a strict allowlist, escalating only when the cheap fix fails.

  1. Detect: a Go watchdog polls Prometheus and raises incidents.
  2. Investigate: a CrewAI orchestrator gathers evidence through four allowlisted MCP tools.
  3. Remediate: restart on the first alert, and double the memory limit only if the problem recurs in the window.

Key decisionA small allowlist beats broad cluster access. With four bounded MCP tools and a two-step escalation, the worst the agent can do is known before it ever runs.

04Synthetic training data

Toolgen

Training data for tool-using agents. It turns ToolBench schemas into grounded multi-turn conversations, with a judge that keeps bad samples out of the dataset.

  1. Build an endpoint graph and sample connected, realistic tool chains.
  2. Execute schema-valid mock tools with session state so the conversation stays consistent.
  3. Judge and repair with an LLM judge that scores naturalness, tool correctness and completion.

Key decisionExecute the tools instead of imagining them. Schema-valid mock responses with session state keep multi-turn data consistent, and a judge-plus-repair loop fixes weak samples instead of quietly keeping them.
